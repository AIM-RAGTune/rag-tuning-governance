\begin{abstract}
This scaffold summarizes the RAGTune governance validation package. The strongest current result is CRAG mock-API governance superiority. A bounded local generative LLM quality-signal audit produced mixed evidence: one CRAG slice reduced measured cost at equivalent generated-answer quality in a 12-example local qwen3 run, but three independent deterministic CRAG repeats did not reproduce the cost result. A second pinned local model, \texttt{gpt-oss:20b}, produced usable quality signals on the same offsets but no positive cost-result slices. A faster non-thinking instruct model, \texttt{llama3.2:3b}, repaired answer emission on larger fixed-offset CRAG slices with zero parse failures, but it also did not recover the cost result. HotpotQA remained inconclusive. Broad generative validation, optimizer superiority for RAG Compass, human evaluation, official external-platform benchmarking, and production readiness are not claimed.
\end{abstract}

\section{Behaviorally Distinct Policy Experiment}
The follow-up experiment reanalyzes sanitized CRAG mock-API frozen observations using candidate policies with different endpoint-routing and operating-cost behavior. The primary endpoint is not a scalar weighted utility difference: governed selection must either reduce measured cost or latency at equivalent proxy-plus-evidence quality, or improve quality under a fixed deployment budget. The current result is \texttt{GOVERNANCE\_REDUCES\_COST\_AT\_EQUIVALENT\_QUALITY}: governed selection chose \texttt{low\_retrieval\_single\_endpoint}, while quality-only selection chose \texttt{optuna\_tpe}. This remains frozen-observation source/retrieval evidence and does not establish human-calibrated, generative, production, or RAG Compass superiority claims.

\section{Generative LLM Validation}
RAGTune Generative LLM Validation v1.1 adds pinned-generator answer generation with sanitized generated-answer metrics, a HotpotQA quality-signal audit, and CRAG generator/evaluator repair. The HotpotQA audit used a bounded 12-example local Ollama \texttt{qwen3:8b} run and found a nonconstant generated-answer quality signal, but governed and quality-only selection chose the same policy. The CRAG primary slice used the restored local CRAG mock-API path and local evaluator mapping after disabling Ollama thinking output for \texttt{qwen3:8b}; the larger bounded 12-example primary sample produced 132 nonempty generated answers and reduced measured cost at equivalent generated-answer quality. Three independent deterministic CRAG repeats at offsets 24, 36, and 60 did not reproduce the cost result. A second pinned local model, \texttt{gpt-oss:20b}, was run on the same four offsets and produced \texttt{CRAG\_GEN\_LLM\_COST\_RESULT\_INCONCLUSIVE\_ACROSS\_REPEATS}. A faster non-thinking instruct model, \texttt{llama3.2:3b}, then repaired answer emission on four 16-example fixed-offset CRAG slices with 0 / 704 parse failures. An unguarded predeclared latency-endpoint selector comparison separated governed and quality-only winners and consistently reduced latency/API calls, but only one slice met generated-quality noninferiority. A quality-risk guarded latency selector avoided quality-loss result classes, but no slice met the latency-reduction CI gate, yielding \texttt{CRAG\_GEN\_LLM\_LATENCY\_RESULT\_INCONCLUSIVE\_ACROSS\_REPEATS}. The synthesis remains \texttt{GEN\_LLM\_SYNTHESIS\_MIXED}.
